# Local processing and site access

Label.ai automatically checks visible media on browser-permitted public pages. The normal extension requests HTTP and HTTPS host access during installation so individual website selection is unnecessary. The browser can restrict or revoke host access. Users can pause globally, and the separate experimental Local Test package is restricted to HTTP loopback pages. Browsing pages show only the positive badge. The extension has no account, telemetry endpoint, analysis service or database.

An image or video already displayed by the page can supply readable pixels. The browser may prevent pixel access to cross-origin media, protected streams and other restricted sources. For a displayed image whose original canvas is unreadable, the scanner can re-read the exact selected public HTTPS image URL through the page's normal CORS permissions. For eligible CSS photo cards, the scanner can also read a single public HTTPS background image on the same origin or a CDN that permits CORS. These anonymous GETs send no cookies, authorization header or referrer. The CDN can see the page origin in the standard Origin header. For pictures, eligible responses are bounded static JPEG, PNG and WebP files. For video, when the displayed player blocks canvas reads, the extension may fetch one complete public MP4 or WebM from the same selected CDN URL under the page’s CORS rules. The 16 MiB and 5-megapixel limits apply before frame capture. A detached, muted decoder reads only times observed during visible playback. The extension never starts or seeks the publisher’s player. Recognized signed URLs, private contexts, redirects, private or no-store responses and canceled reads are excluded. A re-read can supply a pixel estimate only. A mutable URL could serve different bytes. Protected videos and publishers that deny CORS remain outside this route. The original file is required for signature verification. Forming a new JPEG from visible pixels would destroy the original credential. Original-data routes accept bounded embedded bytes or tightly limited public sources. For a same-origin image with a recognized content digest in its address, the extension can request that existing published file with credentials omitted, redirects rejected and the referrer suppressed. Its body is checked locally against the digest. A separate same-origin JPEG or static PNG route uses only the browser's HTTP cache and verifies full-resolution displayed pixel equality before examining an eligible cached original. Already-loaded, immutable same-origin Blob objects may also supply bounded original image or MP4 bytes directly from browser memory. The publisher may see a qualifying download. There is no upload, URL lookup, analytics request, remote trust lookup or cloud fallback.

Model, verification software and trusted roots ship in the install package. Build-time downloads and explicit developer test fixture downloads are different from browsing. Instances and in-flight decisions are short-lived. The extension stores only the global enabled setting and settings version locally. Model errors, private/sensitive paths, permission loss and unsupported sources produce no visible verdict. URL rules and password-form detection cannot recognize every private page on a public host. Pause on authenticated or shared services when the page may contain sensitive material.

Pause, resume or clear local data using the extension's global scanning controls. Browser settings can also withdraw the host permission or remove the extension. The package does not record browsing histories, export media, or collect user reports in the background.
